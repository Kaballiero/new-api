# server/internal — карта модулей

Бизнес-логика backend, разложенная по самостоятельным модулям. Внутри модуля каждый сценарий — отдельный пакет, который читается сверху вниз: `http.go` → `usecase.go` → узкие интерфейсы → адаптеры. Правила структуры — [AGENTS.md](AGENTS.md).

Шлюз к AI-моделям (`relay/`, `relaykit/`, relay-цепочка `middleware/`) сюда не входит: это заменяемая часть, бизнес-модули её не импортируют.

## Модули

| Модуль | Ответственность | Сценариев | README |
|---|---|---|---|
| `accounts` | аккаунты пользователей: создание и регистрация, профиль, группы, квота, привязки email, реферальный код и перевод реферальной квоты, ежедневный check-in, админское управление аккаунтами | 24 | [README](accounts/README.md) |
| `identity` | вход и доказательство личности: пароль, сессии и их отзыв, 2FA и резервные коды, passkey (WebAuthn), OAuth и WeChat, подтверждение email, восстановление пароля, повторная проверка для чувствительных действий | 66 | [README](identity/README.md) |
| `apikeys` | API-ключи пользователей для шлюза: создание, просмотр с маской, раскрытие, изменение, удаление, группы, статус и использование ключа | 16 | [README](apikeys/README.md) |
| `personal_access_tokens` | персональные токены доступа к панели управления (PAT): выпуск, статус, отзыв | 3 | [README](personal_access_tokens/README.md) |
| `authorization` | права администраторов (Casbin): каталог разрешений, проверка, переопределения для пользователя, загрузка политики | 11 | [README](authorization/README.md) |
| `catalog` | каталог моделей и вендоров: CRUD, синхронизация метаданных, модели без настроек | 26 | [README](catalog/README.md) |
| `pricing` | цены для клиентов: публичная и персональная страница цен, конфигурация цен и коэффициентов, сборка и публикация каталога цен из upstream | 25 | — |
| `channels` | администрирование каналов к провайдерам: CRUD, теги, ключи, баланс, проверка каналов, обновление моделей upstream, Codex-учётные данные, Ollama | 51 | — |

README каждого модуля появляется в коммите, который чистит или переносит этот модуль.

## Служебные части

| Папка | Что внутри |
|---|---|
| `app/` | сборка зависимостей модулей и HTTP-обработчики для `controller/`; один файл на модуль |
| `adapter/gorm/<module>` | хранение через GORM |
| `adapter/settings/<module>` | чтение настроек |
| `adapter/casbin`, `adapter/identity`, `adapter/channels`, `adapter/pricing`, `adapter/catalog` | технические реализации интерфейсов модулей |
| `adapter/http` | пока смешаны входящий транспорт и исходящие клиенты; по правилам входящее переедет в `<module>/transport/` (у `apikeys`, `accounts` и `catalog` уже в `<module>/transport/`) |
| `contracttest/` | заготовка контрактных HTTP-тестов |
| `architecture_test.go` | проверка правил импортов; текущий долг — `architecture_known_violations_test.go` |

## Ещё не перенесено

Платежи и пополнение баланса, подписки, коды погашения, логи и статистика использования, настройки и системные функции, деплойменты, batch, а также шлюз и асинхронные задачи (`relay/`, `controller/relay.go`, `task*`). Пока они живут в `controller/`, `service/` и `model/`.
