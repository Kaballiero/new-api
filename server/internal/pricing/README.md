# pricing — цены для клиентов и конфигурация цен

## Ответственность

Модуль владеет тем, как платформа показывает и настраивает цены моделей:
- каталог цен (`Pricing`) — снимок, собранный из моделей, каналов, коэффициентов, billing-выражений и нативных цен upstream; его ревизия (`catalog_revision`) и публикация;
- проекция цены для потребителя (`Projection`): тариф группы, FX-пересчёт в рубли, страницы, обзор, детальная карточка модели, публичный каталог, минимальные цены предложений upstream;
- конфигурация цен моделей в опциях (`Configuration`): версии цены модели, проверка значений и выражений, встроенные цены;
- сравнение коэффициентов с upstream (ratio sync);
- резерв запроса шлюза к OpenRouter по тарифам endpoint'ов upstream (`estimate_upstream_reserve`) и резерв видеозаказа по видеотарифам upstream (`estimate_upstream_video_reserve`).

Инварианты:
- значения цен, коэффициенты, состав каталога, ревизии, публикация и кэш потребительского каталога — источник истины для страниц цен; рефакторинг их не меняет;
- чтение с `expected_revision` отдаётся только для той же ревизии, иначе 409 `pricing_catalog_revision_mismatch`;
- изменение цены модели применяется только к версии, которую видел клиент (`expected_version`), иначе конфликт `ErrModelPricingConflict`;
- публикация выбранного upstream-каталога и синхронизация идут только для неизменённого источника (`ErrCatalogSourceChanged`);
- ревизия upstream-каталога, потерявшая больше `MaxCatalogModelLossPercent` (30%) опубликованных моделей (`CatalogModelLoss`), не применяется. Опубликованные модели — модели head, которые запрашивают каналы (`CatalogRequestedModels`: модель тарифа `UpstreamTariffModel` upstream-модели каждой ability включённого канала OpenRouter каталога, то есть без shortcut `:nitro`/`:floor`); цели alias, варианты `:batch` и модели, которые больше никто не запрашивает, не сравниваются. Одно правило для цен и каналов: head не двигается (`CatalogModelLossError`), а модели каналов из неё не применяются автоматически (`UpstreamModels.AutoApplyBlocked`);
- цена модели upstream-каталога — минимальные цены синхронных предложений её документа для операции её типа (`Projection.CatalogModelMinimumPrices`). По этому правилу `list_upstream_catalog_models` подтверждает цену добавляемой модели, а `sync_upstream_catalog` сравнивает цены двух ревизий (`CatalogPriceChanges`): компонент попадает в отчёт, если цена выросла или упала больше чем в `PriceChangeFactor` (2) раза, в том числе бесплатный компонент, получивший цену. Отчёт только информирует и head не задерживает.

Понятия и бизнес-ошибки — в `domain/` (проекция, конфигурация, каталог, ratio sync, нормализация нативных цен, чтение цены endpoint'а `endpoint_price.go`, `errors.go`). Правила billing-выражений — `pkg/billingexpr/expr.md`.

| `refresh_catalogue` | прогон фоновой задачи обновления нативных цен upstream и публикации каталога. Отклонённая ревизия upstream-каталога (`CatalogModelLossError`) завершает задачу ошибкой, пропавшие модели попадают в `lost_models` summary, а алерт уходит в Telegram-чат один раз на ревизию: ревизия последнего доставленного алерта — строка `pricing_catalog_rejected_revision` таблицы `options` (`SentAlerts`, `CatalogAlerts`). Цены, которые применённая ревизия изменила больше чем в 2 раза, попадают в `price_changes` summary (в USD) и отдельным сообщением в Telegram-чат (`CatalogAlerts.PriceChanges`): ревизии сокращены до 12 символов, суммы — в ₽ по текущему курсу, а без курса — в USD. Отправка пишется в лог; недоставленный отчёт тоже пишется в лог и не повторяется: head уже сдвинулся, следующий прогон сравнивает с ним | системная задача `pricing_catalog` (`app/systemruntime`) |
| `enqueue_catalogue_refresh` | постановка задачи обновления (`PRICING_CATALOG_TASK_ENABLED`) | без HTTP, `app.NewEnqueuePricingCatalogueRefresh` |
| `sync_upstream_catalog` | синхронизация upstream-каталога в неизменяемые записи; опубликованные новые документы передаются раскодированными в общий кэш документов. Вместе с запрошенной моделью берётся её вариант `:batch` (`UpstreamTariffModel(model, true)`), если manifest его перечисляет: по нему считается резерв Batch. Вариант не входит в `MissingModels`, `ImportedModels` и сравнение `CatalogModelLoss`, а в отчёт об изменении цен не попадает: отчёт сравнивает синхронные минимальные цены, которых у варианта `:batch` нет. Manifest сравнивается с опубликованными моделями (`CatalogModelLoss`): при потере больше 30% из них возвращается `CatalogModelLossError`, head не меняется; пока ревизия отклонена, не применяются и изменения цен оставшихся моделей, а модель, добавленная в канал за это время, не получает цену каталога до движения head. Пропавшие модели, убранные из каналов, в сравнение не входят, поэтому следующая ревизия проходит. Перед публикацией цены моделей, которые head и новая выборка публикуют разными документами, сравниваются по `CatalogPriceChanges` при ratio 1, как при подтверждении `Addable`: кратность изменения не зависит от курса. Изменения записываются в USD вместе с remote-ревизиями head и новой ревизии (`CatalogPriceChangeReport`); документы head читает `LoadStoredCatalogDocuments`. Документ меняет ревизию, поэтому сравнение идёт только при смене head; отклонённая ревизия не сравнивается. Отчёт только информирует: если сохранённый документ head не читается, сравнение пропускается, ошибка попадает в `price_changes_error` summary и в лог, а ревизия публикуется | без HTTP, `refresh_catalogue` и outer `app/pricing.go` |
| `ensure_catalog_source`, `publish_catalog_selection` | источник upstream-каталога и публикация выбранных записей | без HTTP, native characterization; persistence API у `adapter/gorm/pricing` |
| `read_upstream_catalogue` | проекция upstream-каталога: документы опубликованной ревизии читает `LoadStoredCatalogDocuments`, документы, на которые ревизия больше не ссылается, освобождаются из кэша. Тарифы endpoint'ов ревизии (`CatalogEndpointTariffs`: offer `scope=endpoint` с `eligibility.eligible=true`; модель, у которой такой offer без тега провайдера, без объекта `facts.pricing` или с нечитаемыми capabilities/variant, в тарифы не попадает и считается live; цены за единицу endpoint'а — `CatalogUnitPrices`: компоненты `model_page`, цена = `amountUSD / quantity`, максимум по вариантам и условиям `utcDay` в каждом измерении (billable + unit из `character`, `utf8_byte`, `second`, `search`, `million_tokens`), `null` остаётся неизвестной, компонент без billable или в другой единице — неизвестное измерение) и видеотарифы ревизии (`CatalogVideoTariffs`: запись `/videos/models` из `facts.raw.video_api` подходящего endpoint-offer'а; модель без такой записи, с несколькими записями, с нечитаемыми facts или с записью другой модели в видеотарифы не попадает и считается live) публикуются целиком вместе с `fetchedAt` head (`UpstreamCatalogTariffs`: `Models` и `Videos`) для резерва OpenRouter. Ревизия читается и отображается в тарифы один раз: если ревизия head не сменилась (сменился только `fetchedAt`), читается только head по первичному ключу, а документы и их hash берутся из ревизии, прочитанной в прошлый раз (`read_upstream_catalogue.Revision`, экземпляр в `app/pricingruntime`). Опубликованные тарифы читаются до head и заменяются, только если с тех пор их никто не заменил (`CompareAndSwap`), поэтому медленное чтение не публикует старый head поверх нового. Без опубликованной ревизии тарифов нет; ошибка чтения оставляет опубликованные | без HTTP, `app/pricingruntime`: при пересборке каталога и раз в `SYNC_FREQUENCY` на каждом узле (`RefreshUpstreamCatalogTariffs` в `app/settings.SyncOptions`; вместе с чтением ревизии для отпечатка входов каталога — два запроса head по ключу в минуту на узел) |
| `list_upstream_catalog_models` | модели опубликованного upstream-каталога как `channels/domain.UpstreamModels` канала OpenRouter: `Listed` — модели manifest, `Addable` — те из них, что не alias, без суффикса `:free` и `:batch`, с операцией текста, эмбеддингов или генерации изображений по типу (`CatalogConsumerProfile`) и пути запроса из index, и с подтверждённой ценой синхронного предложения (`Projection.CatalogModelMinimumPrices` → `ConfirmedConsumerPrices`); `Shortcuts` — shortcuts маршрутизации OpenRouter (`OpenRouterShortcuts`: `:nitro`, `:floor`). `ReserveRefused` — добавляемые модели текста и эмбеддингов, чей резерв эталонного запроса (`chat/completions` или `embeddings`) не считается по тарифам эндпоинтов документов кандидатов (`CatalogEndpointTariffs`), с причиной отказа; порт `ReserveChecker` реализует `adapter/gateway/pricing.CatalogReserves`. Модель генерации изображений не проверяется: её резерв считается по live-данным. Manifest и index читаются одной ревизии (при расхождении — одна повторная попытка, затем ошибка). Документы кандидатов загружает `LoadCatalogDocuments` (общий с `sync_upstream_catalog`: сохранённые — через `LoadStoredCatalogDocuments`, недостающие — из каталога, без сохранения); результат ревизии хранится в процессе (`adapter/pricing.UpstreamCatalogModelsCache`), поэтому документы ревизии читаются один раз. `AutoApplyBlocked` — manifest потерял больше 30% опубликованных моделей по тому же правилу `CatalogModelLoss`, что и `sync_upstream_catalog` (abilities и каналы читает `domain.CatalogChannels`, реализация `adapter/pricing/upstream.NativeStore`); флаг считается на каждый вызов, в том числе для результата из кэша; нечитаемый head — ошибка | без HTTP, `channelModelFetcher` в `app/channels.go` |
| `estimate_upstream_reserve` | резерв запроса шлюза к OpenRouter в USD — максимум стоимости по подходящим endpoint'ам всех маршрутизируемых моделей запроса. Endpoint отбирают фильтры провайдера (`only`, `ignore`, `order` при `allow_fallbacks: false`, `quantizations`, `require_parameters`, `max_price`), service tier (`priority`/`fast`, `flex`, `ultrafast` — только по запросу, явному slug или shortcut `:nitro`/`:floor`; `ultrafast` допускает и priority-endpoint'ы), лимиты контекста и вывода (без лимита клиента вывод ограничен `DefaultOutputTokens`); default-endpoint, на который откатывается запрос `flex`, исключается, если по цене ввода или вывода он дороже каждого подходящего flex-тарифа. Тарифы по длине промпта и окнам UTC (`overrides`) дают несколько вариантов, в резерв идёт наибольший. Речь, rerank и транскрибация (`Input.Units`) считаются только по ценам за единицу endpoint'а (`domain.EndpointUnitPrice`, из компонентов `model_page` каталога, `domain.CatalogUnitPrices`): каждая ненулевая цена × измеренное количество (`million_tokens` — за миллион токенов; аудиотокены вывода — лимит вывода endpoint'а), нулевая цена пропускается; нет цен за единицу (live их не публикует), цена `null`, ненулевая цена неизмеренного измерения или ненулевая ставка `pricing` endpoint'а, которую цены за единицу не покрывают (покрыты только `prompt`/`completion`, равные цене за единицу или сумме, которую публикует любой компонент её измерения (`amountUSD / quantity` или сам `amountUSD`, `EndpointUnitPrice.PublishedUSD`), — за токен для `million_tokens` — или такой сумме после скидки endpoint'а; резерв по-прежнему по наибольшей цене), — `domain.EstimateUnavailableError` без перепроверки через live. Для rerank шлюз измеряет и поиски Cohere, и входные токены, считая токеном каждый байт UTF-8 запроса и документов (верхняя граница для byte-level BPE); endpoint считает то измерение, у которого есть цена. Поиски запроса на встроенном поиске (`Input.Searches`, не больше 32) стоят цену `web_search` endpoint'а за каждый, ручной резерв канала к ним не прибавляется (`searchCost`); цены нет в свежем каталоге — модель перепроверяется через live, нет и там — их покрывает резерв канала для поиска (`SearchReserveUSD`, только endpoint'ы модели запроса), без него — `domain.ErrHostedSearchUnpriced`. Поиск движком без цены endpoint'а (`Input.ManualSearch`) добавляет резерв канала для поиска, и к поискам встроенного; без резерва — отказ; без запрошенных поисков endpoint с положительной ценой `web_search` может искать сам (модели Perplexity Sonar) и стоит один поиск; цены нет в свежем каталоге — перепроверка через live, нет и там — поиск не тарифицируется. Ручной резерв канала у текста по тарифам (`Input.FloorReserveUSD`) — нижняя граница: резерв — максимум оценки (с поисками и резервом для поиска) и этой суммы; если сумма больше оценки, источник резерва — `manual`. Decisions считаются обычным расчётом endpoint'а: токены промпта (шлюз считает state и вопросы по байтам UTF-8 — байт за токен, верхняя граница для byte-level BPE, у любой модели) по цене `prompt`, цена `request` и поиски — по одному на вопрос, не больше 100, — по цене `web_search` endpoint'а; endpoint без `web_search` поиски не тарифицирует. Лимиты контекста endpoint decisions из резерва не исключают: граница по байтам может превышать контекст endpoint'а, на который OpenRouter всё равно маршрутизирует. Ненулевая ставка `completion` или `internal_reasoning` (decisions не измеряют вывод), отсутствующая или неверная цена — `domain.EstimateUnavailableError`: отсутствующая цена свежего каталога перепроверяется через live, затем такую оценку покрывает только ручной резерв канала, иначе отказ. Неизмеримое количество (аудио Chat, неизвестный тариф) — `domain.EstimateUnavailableError`: его покрывает только ручная цена или приблизительный резерв канала; при резерве — нижней границе ошибка возвращается с первого такого endpoint'а, и шлюз повторяет оценку целым резервом. Для текстового резерва по тарифам возвращает границы подсказки `max_tokens` (`InputUSD`, `PromptPriceUSD`, `OutputPriceUSD`, `OutputTokens`). Тарифы каждой маршрутизируемой модели берутся по модели тарифа `UpstreamTariffModel` (без `:nitro`/`:floor`, для Batch — вариант `:batch`), по одному разу на модель тарифа. Каталог считает только генерацию текста (без вывода картинок и аудио), эмбеддинги, речь, rerank, decisions и транскрибацию, в том числе Batch, и только у канала на официальном URL OpenRouter (`IsOpenRouterCatalogBaseURL`); аудио Chat и вывод картинок считаются live. Такая модель берёт документ опубликованного каталога (`UpstreamCatalogTariffs`), если данные каталога не старше `PRICING_CATALOG_MAX_AGE_HOURS` (1–8760 ч, по умолчанию и при неверном значении 24 ч; читается один раз в `app/pricingruntime`): `now − fetchedAt ≤ X`; иначе — live через порт `LiveTariffs`; если live не ответил — устаревший документ (его пустой или суженный фильтрами пул, как ниже, покрывают только ручная цена или резерв канала, иначе отказ ошибкой live), а без документа возвращается ошибка live. Модель свежего каталога перепроверяется через live по отдельности, если у неё нет нужной цены (отсутствует или `null`, `ErrEndpointPriceMissing`), ни один её endpoint не прошёл фильтры или `provider.require_parameters` исключил хотя бы один из них: она считается заново по live, остальные модели — по каталогу, резерв — максимум по всем. Если live при перепроверке не ответил: отсутствующую цену документ считает так же, как live, — её покрывают ручная цена или резерв канала, иначе прежний отказ; пустой или суженный фильтрами пул модели резерв не считает (иначе резерв мог бы оказаться ниже live) — модель покрывают только ручная цена или резерв канала, иначе запрос отклоняется ошибкой live, в том числе когда у других моделей запроса endpoint'ы есть. Тексты ошибок прежние. Batch, как и раньше, не проверяет объявленные модальности вывода. Источник резерва (`Estimate.Source`, `domain.ReserveSource`) — сумма, которая задала резерв: `configured_price` (ручная цена) или `manual` (приблизительный резерв канала или нижняя граница), только если она больше оценки по тарифам; иначе по моделям `catalog_stale` > `live` > `catalog`. При ручной цене удерживаемая сумма — максимум из ручной цены и резерва канала, и `configured_price` относится к этой сумме, даже если её задал резерв канала; `Estimate.StaleCatalog` отмечает устаревший документ при любом источнике | без HTTP, `relay/channel/openrouter.RequestEstimator` через `app/pricingruntime.EstimateUpstreamReserve` |
| `estimate_upstream_video_reserve` | резерв видеозаказа шлюза к OpenRouter в USD по видеотарифу модели (`domain.VideoModelPricing`): цену заказа считает порт `VideoOrder` (правила SKU шлюза), сценарий выбирает тариф. Порядок источников тот же, что у текста (`domain.ModelTariff`): каталог (`UpstreamCatalogTariffs.Videos`) — только у канала на официальном URL OpenRouter и пока данные каталога не старше `PRICING_CATALOG_MAX_AGE_HOURS`; иначе — live через порт `LiveVideoTariffs`; если live не ответил — устаревший документ (`catalog_stale`), без документа — ошибка live. Если заказ не считается по свежему тарифу каталога, тариф один раз перепроверяется через live: цену считает live-тариф, а если live не ответил, остаётся ошибка каталога. Ручного резерва канала для видео нет: заказ без цены отклоняется, как раньше. Возвращает USD и источник (`catalog`, `live`, `catalog_stale`) | без HTTP, `relay/channel/openrouter.EstimateVideo` через `app/pricingruntime.EstimateUpstreamVideoReserve` |
| `preview_channel_reserves` | таблица резервов канала OpenRouter только на чтение: строки — модели канала (через маппинг моделей, `ResolvePricingUpstreamModel`; неразрешимый маппинг — `refused` без upstream-модели) и ключи настроек резерва моделей вне канала (`in_channel: false`) с настроенным источником (`configured_source`) и ручной суммой (`manual_usd`, вместе с устаревшим резервом Sonar). Пример — резерв эталонного запроса (non-stream `chat/completions`, 1000 токенов промпта, без `max_tokens`: шлюз берёт 8192 с учётом лимита endpoint'а; модель каталога, у которой вывод только `embeddings`, — `embeddings`; с выводом `speech` — речь OpenAI Audio из 100 символов `a`; с выводом `rerank` — Rerank короткого запроса по трём коротким документам; операция эталона строки — `reference_operation`), посчитанный кодом допуска шлюза (`openrouter.EstimateRequestReserve`) на оценщике без привязанного запроса: live-запроса нет, модель, которой нужен live, — `needs_live_check` (`domain.ErrEndpointDiscoveryMissing` или отсутствующая цена), прочий отказ шлюза — `refused`, текст ошибки шлюза — `example_error`. Без опубликованного или с устаревшим каталогом, у канала не на официальном URL, у модели вне каталога или без вывода текста, эмбеддингов, речи и rerank пример не считается (`live_only`). Для каждого тега endpoint'а модели каталога тот же запрос с `provider.only=[тег]` и `ignore` его подтегов (`tag/…`) даёт строку провайдера с `tier` (`domain.EndpointServiceTier`); отказ — `usd: null`; у речи строк провайдеров нет (фильтры провайдера шлюз у речи отклоняет). Источник (`effective_source`) и политика (`admission_policy`, `domain.AdmissionPolicy`) — те же значения, что пишет admin-лог. Не OpenRouter — 400 i18n `pricing.channel_not_openrouter`; нет канала — 404 `channel_not_found` | `GET /api/channel/:id/openrouter_reserves`, `AdminAuth` + `authz.ChannelRead` |
| `rebuild_catalogue` | сборка снимка каталога цен | без HTTP, `app/pricingruntime` + `adapter/pricing/state` |
| `read_catalogue` | ревизия опубликованного каталога | без HTTP, `app/pricingruntime` + `adapter/pricing/state` |
| `publish_native_catalogue` | публикация нативных цен в опции | без HTTP, `app/pricingruntime` + `adapter/settings/publication` |
| `observe_catalogue_inputs` | отпечаток входных данных каталога | без HTTP, `app/pricingruntime` + `adapter/pricing/state` |
| `update_pricing_options`, `mutate_pricing_options` | запись опций цен вне HTTP-конфигурации | без HTTP, `app/pricingruntime` |

Ошибки чтения цен и ratio sync переводит в HTTP общий `transport.WriteError` (тело `{success:false, message}` без `Abort`):
- `ErrRevisionMismatch` → 409 с `code: pricing_catalog_revision_mismatch`;
- `domain.InvalidQuery(err)` (ошибки разбора запроса, `invalid using_group`) и `ErrInvalidUserGroup` → 400, текст причины;
- `ErrUserGroupUnavailable` → 500; `ErrChannelQueryFailed` → 500 с i18n `channel.query_failed` (раньше «查询渠道失败»);
- `ErrModelPricingUnavailable` → 404;
- `ErrNoUpstreams` → 200 с i18n `channel.no_valid_upstream` (раньше «无有效上游渠道»);
- `channels/domain.ErrChannelNotFound` → 404 `channel_not_found` с i18n `channel.not_exists`, как у соседних `/api/channel/:id`; `ErrChannelNotOpenRouter` → 400 с i18n `pricing.channel_not_openrouter`;
- остальное, включая `ErrPublicPricingUnavailable` и ошибки чтения снимка/FX, → 503 с текстом ошибки.

Остальные ответы:
- `update_pricing_config`: ошибка JSON → 400; `ErrModelPricingConflict` в цепочке → 409; прочие ошибки проверки → 400; всё с текстом ошибки;
- `get_pricing_config`: ошибка → 200 `{success:false}` (`common.ApiError`); `list_syncable_channels` — так же;
- `get_ratio_config`: выключено → 403 `ratio_config_disabled` с i18n `pricing.ratio_config_disabled` (раньше «倍率配置接口未启用»);
- `fetch_upstream_ratios`: неверное тело → 400 с i18n `pricing.request_invalid` (раньше «请求参数格式错误»); нераспознанный ответ upstream в `test_results[].error` — i18n `pricing.upstream_data_unrecognized` (раньше «无法解析上游返回数据»);

OpenAPI-генератор (`cmd/gen-admin-openapi/pricing.go`) читает DTO и `http.go` сценариев, а контракт ответов и коды ошибок берёт из своей таблицы `pricingHandlerSources`.

## Зависимости

- `catalog/domain` (`Model`, `Vendor`, метаданные) — цена строится поверх модели; `channels/domain` — поверх канала (`domain/catalogue.go`).
- Сборка — `internal/app/pricing.go` (`NewPricingHTTP`), один раз через `sync.OnceValue` в `app/httpapi/pricing.go`; аудит — callback app/httpapi к app/audit.Recording.
- Документы upstream-каталога неизменяемы и адресуются hash. `LoadStoredCatalogDocuments` берёт сохранённый документ из кэша по источнику и hash (`domain.CatalogDocumentCache`, реализация `adapter/pricing.UpstreamCatalogDocumentsCache`, экземпляр `app/pricingruntime.UpstreamCatalogDocuments`), остальные читает из БД, раскодирует с проверкой и кэширует. Повторно документ раскодируется, только если кэш его освободил (ревизия на него больше не ссылалась) или если два сценария одновременно впервые читают его. Кэш общий для `read_upstream_catalogue`, `sync_upstream_catalog` и `list_upstream_catalog_models`; в нём только сохранённые документы: загруженные из каталога попадают туда после публикации. Тарифы опубликованной ревизии (`domain.UpstreamCatalogTariffs`) держит `app/pricingruntime.UpstreamCatalogTariffs` (`atomic.Pointer`): публикация заменяет их целиком, опубликованные map не меняются, поэтому читатели берут их без блокировки; в памяти только тарифы последней ревизии.
- Адаптеры: `adapter/pricing` (`Reader`, `ConsumerCache`, `ProjectionCache`, `RatioSettings`, `RatioChannels`, `UpstreamCatalogModelsCache`, `UpstreamCatalogDocumentsCache`, плагины, тексты алерта отклонённой ревизии `CatalogModelLossNotification` и отчёта об изменении цен `CatalogPriceChangesNotification`; отправку в Telegram-чат на языке root собирает `app/pricing.go`), `adapter/gorm/settings` (строка `pricing_catalog_rejected_revision`), `adapter/pricing/upstream` (HTTP-клиенты ratio sync и нативных цен, override, нормализация), `adapter/gorm/pricing` (опции, каталог, неизменяемые записи, наблюдения).
- Настройки: `setting/ratio_setting`, `setting/billing_setting`, account group policy в settings/accounts. Leaf `app/pricingruntime` собирает статические сценарии once; `adapter/pricing/state` владеет единым опубликованным snapshot, revision/generation/observation state и lock order. DB, колонки, настройки, registry и clock читаются поздно.
- Модели upstream-каталога (`list_upstream_catalog_models`) возвращаются как `channels/domain.UpstreamModels`; сценарий собирает `app/pricing.go`, вызывает обновление моделей каналов через `app/channels.go`.
- Включённый канал OpenRouter каталога, чей маппинг моделей не разрешается (неверный JSON или цикл), делает опубликованные модели неизвестными: `CatalogRequestedModels` возвращает такие каналы отдельно от запрошенных моделей. `refresh_catalogue` тогда завершается ошибкой, и head не двигается; `list_upstream_catalog_models` отдаёт модели с `AutoApplyBlocked` и этими каналами в `UnresolvedMappingChannels` (также без опубликованного head), поэтому плановая проверка каналов ничего не применяет, а ручные проверка и применение работают.
- Потребители: `controller/pricing*.go`, `ratio_sync.go`, `ratio_config.go`, `model_pricing_config.go` (HTTP bindings и wire-декларации OpenAPI); `app/pricingruntime` и технические adapters (сценарии без HTTP).
- Шлюз (`relay/channel/openrouter.RequestEstimator`, в том числе admission Batch через `adapter/gateway/batch`) берёт `estimate_upstream_reserve` из `app/pricingruntime.EstimateUpstreamReserve`; сценарий создаётся один раз и получает `domain.Capabilities` (использует только `Codec`), тарифы каталога `app/pricingruntime.UpstreamCatalogTariffs`, часы и предельный возраст каталога функциями. Порт live-тарифов (`LiveTariffs`) реализует шлюз (`relay/channel/openrouter/live_tariffs.go`: прежний `RequestEstimator.Discover` по `/endpoints`, один раз на модель тарифа за запрос) и передаёт во входе вызывающий код relay; запрос и адаптер для него шлюз привязывает `RequestEstimator.Bind`. Тариф endpoint'а — `domain.NativePricedEndpoint`, live-ответ шлюз преобразует в `domain.NativeEndpointResponse` (`PricedEndpoint.Tariff`, без цен за единицу). Количества речи измеряет шлюз (`relay/channel/openrouter/speech_units.go`): символы и байты UTF-8 ввода точно; секунды — приближение: большее из ceil(слова / 2) и ceil(символы / 5), делённое на min(`speed`, 1) (медленная речь удлиняет, быструю провайдер может проигнорировать; `speed` вне 0.25–4 — отказ); входные токены — сумма токенов ввода и `instructions` токенизатором (верхняя граница). Аудиотокены вывода — лимит вывода endpoint'а (`max_completion_tokens`), без лимита — `DefaultPreConsumeMaxTokens`; секунды транскрибации — наибольшая длительность из заголовков аудио (`relay/channel/openrouter/transcription_seconds.go`, `common.GetAudioDuration`) по расширению файла (`.mpga`/`.mpeg` как MP3) и по сигнатуре формата в начале файла, у WAV — не меньше длительности байтов после заголовка блока data; не больше `transcriptionMaxSeconds` (24 ч), округлённые вверх. Для канала OpenRouter транспорт не считает аудио транскрибации в токены (`tokenusage.CountRequestToken`), при переходе на прямой канал оно считается заново; нечитаемую длительность покрывает только ручная цена или резерв канала, без них — отказ. Резерв канала для речи и транскрибации не обязателен, а если задан — резерв равен максимуму из рассчитанного и ручного; источник `manual`, только если ручной больше рассчитанного. Источник резерва шлюз пишет в admin-лог (`openrouter_reservation_source`, `adapter/gorm/usage`; у каждой синхронной задачи OpenRouter — из фактов заказа задачи `reservation_source`, в логах резерва и расчёта), рядом — измеренные количества, по которым посчитан резерв (`openrouter_reservation_quantities`, `domain.ReserveQuantity`: `searches`, `prompt_tokens` у decisions, `audio_seconds` — секунды транскрибации; цепочка `RequestEstimator.ReserveQuantities` → `OpenRouterCostState.ReserveQuantities`); для Batch источник не сохраняется. Устаревший документ (`Estimate.StaleCatalog`) шлюз отмечает предупреждением в логе и для Batch, и при источнике `configured_price`/`manual`. `domain.ReadEndpointPrice` читает цену endpoint'а и при нормализации нативных цен (`NativeNormalizer`).
- `preview_channel_reserves` читает канал через `adapter/pricing/upstream.NativeStore` (`BuildChannel`, `IsMissing`), тарифы каталога — `app/pricingruntime.UpstreamCatalogTariffs`, предельный возраст — `app/pricingruntime.CatalogMaxAge`. Порт `ReservePreviewer` (настройки резерва канала и пример) реализует `adapter/gateway/pricing.ChannelReserves`: собирает `RelayInfo` канала (тип, базовый URL, настройки, формат OpenAI, Embedding, OpenAI Audio или Rerank) и эталонное тело и вызывает `openrouter.EstimateRequestReserve` — ту же проверку источника, настроенную цену и оценку, что `PrepareRequest`. Оценщик без `Bind` live не обнаруживает (`domain.ErrEndpointDiscoveryMissing`); устаревший каталог сценарий в шлюз не передаёт.
- `adapter/gateway/pricing.CatalogReserves` (порт `ReserveChecker` сценария `list_upstream_catalog_models`, собирает `app/pricing.go`) вызывает `openrouter.EstimateRequestReserve` с тем же эталонным запросом, что и предпросмотр резервов (`ReferencePromptTokens` токенов промпта), для канала OpenRouter с официальным базовым URL и без настроек. Оценщик `openrouter.NewCatalogEstimator` считает резерв по переданным тарифам (свежим на момент проверки) и без `Bind` live не обнаруживает, поэтому проверка не обращается к OpenRouter и не учитывает ручной резерв и настроенную цену.

## Границы и долг

- Модулю не принадлежат каналы (модуль `channels`) и метаданные моделей (модуль `catalog`).
- ⚠ Каналы для ratio sync читаются через `adapter/gorm/channels` в `app/pricing.go` (`GetChannelsByIds`, `GetAllChannels`, `GetChannelById` + `GetNextEnabledKey` для ключа OpenRouter), а не через сценарии `channels`.
- ⚠ `adapter/gorm/pricing` и `adapter/pricing/upstream` используют записи `adapter/gorm/catalog/record` и `adapter/gorm/channels/record` напрямую.
- `domain` и сценарии транзитивно не зависят от `common`, `billingexpr`, `jsplugin` и `catalogsync` и не импортируют gateway DTO. Единственный разрешённый gateway leaf — прежняя цепочка `constant → relaykit/types → relaykit/relayconvert/kitutil` для EndpointType/FinishReason. Правило `pricing-constant-alias-leaf` проверяет точные пакеты и рёбра; direct business imports gateway и любые другие gateway paths запрещены. Выделение constant leaf относится к необязательной волне 9. Offer/document/schema/tier/display facts принадлежат pricing; `Capabilities` явно передаёт codecs, expression/catalog readers и endpoint rules. Арифметика и expression engine остаются в прежних пакетах.
- `adapter/pricing` преобразует native facts по полям с сохранением wire-представления. Enum labels кодируются прежним `jsplugin.LocalizedText.MarshalJSON` в raw display facts, поэтому nil label остаётся `{}`; description сохраняет map и прежний `omitempty`. Typed persisted catalog decoder сохраняет прежние SDK wire-типы и исходные UnmarshalTypeError Type/Struct/Field/Offset facts для domain containers, включая точные тексты ошибок. Alias resolver собирается один раз на snapshot и вызывает прежний `catalogsync.ResolveAlias`.
- Ratio request/result DTO принадлежат своим сценариям; общий `RatioDifference` — domain. HTTP передаёт прежний Gin binder codec-адаптеру: тот использует исходный wire request и validation, затем отображает его в plain Request. Поэтому названия типов в диагностике binding остаются прежними. `AdvancedEndpoints` и `ChannelCodec` оставляют relay DTO и их parsing в адаптере.
- Резерв OpenRouter: шлюз обнаруживает endpoint'ы (`/endpoints`), когда сценарий просит live, разбирает запрос, проверяет формат и стрим, измеряет количества (токены промпта, `n`, картинки, правило Cohere Embed, поиски — `relay/channel/openrouter/web_search.go`: инструменты `openrouter:web_search` — `max_uses` или 30, вместе не больше `max_tool_calls` и 30, плюс по одному за плагин `web` и `web_search_options`; `max_uses`/`max_tool_calls` (последний — только при инструменте) меньше 1 или не целые — 400; движок `auto`/`native`/без движка — встроенный поиск, другие — резерв канала; `:online`, Batch и `stop_server_tools_when` с поиском отклоняются), нормализует slug провайдеров (нижний регистр, `/priority` → `/fast`) и применяет политику резерва (ручная цена, приблизительный резерв, нижняя граница, резерв для поиска, повтор целым резервом). Проверки политики перемешаны с проверками формата и стрима, их перенос изменил бы порядок ошибок. Константы шлюза (`DefaultOutputTokens`, `MaxTokensLimit`) приходят во входе: импорт `relay/helper` дал бы цикл.
- Свежесть каталога для резерва считается по `fetchedAt` manifest, сохранённому в head, а не по `checked_at`: каталог сейчас обновляют вручную, и `fetchedAt` меняется, только когда меняются данные. `checked_at` оставался бы свежим, пока цены устаревают на дни; ложное «устарел» лишь отправляет резерв в live, как до каталога. Алерт об устаревшем каталоге в Telegram не сделан: он нужен после автообновления каталога.
- Каталог и live расходятся в `max_completion_tokens`: live бывает меньше опубликованного, а `null` в каталоге — без лимита, поэтому каталог допускает не меньше endpoint'ов и резерв не меньше live. `supported_parameters` live содержит `reasoning_effort` у каждого endpoint'а с `reasoning`, каталог — лишь у части; `CatalogEndpointTariffs` добавляет `reasoning_effort` к `reasoning` (сверено с live 17.11.2026: 7 моделей, 65 endpoint'ов, совпадение полное). `quantization` и в каталоге, и в live — `"unknown"` у неизвестной квантизации и сравнивается как есть, поэтому фильтр `provider.quantizations` отбирает одинаково.
- Правила цены медиазаказов остаются в шлюзе: SKU видео (`EstimateVideoOrder`, порт `VideoOrder`) и резерв картинок по уровню и размеру запроса (`relay/channel/openrouter/image_reserve.go`); переносить в `internal/pricing`, когда появится второй потребитель.
- Правила `estimate_upstream_reserve` близки к `NativePricingVectors` и `CatalogServiceTierAllowed`, но не объединены: у них другие тексты ошибок, границы порога промпта и правило `ultrafast`. Тексты ошибок резерва уходят клиенту по-английски, без i18n.
- Сценарии создаёт app. `adapter/settings/publication` предоставляет один publisher/lock для settings, legacy pricing options и native publication; каталожные удаления получают same-tx техническую capability.
- Бизнес-ошибки принадлежат pricing/domain; model сохраняет только строгие table aliases для immutable catalog records.
- Имена пресетов «官方倍率预设» / «models.dev 价格预设» в `list_syncable_channels` — идентификаторы, с которыми сравнивает клиент (`client/src/features/system-settings/models/constants.ts`); не локализуются.
- `consumerContext` используется сценариями чтения и диагностикой `list_unbillable_models`. Публичные страницы скрывают модели без подтверждённой цены (явный ноль считается ценой) и без возможности биллинга; персональные страницы и overview сохраняют полный состав. Eligibility читает catalog owner через узкий порт, minute cache принадлежит `adapter/pricing`. После успешного refresh диагностические причины добавляются в summary и лог.
- Creator берётся из сохранённых metadata, затем catalog author, затем эвристики имени; display vendors не записываются в БД. Context window добавляется как display tag только при отсутствии сохранённого K/M tag.

ResetModelRatios пишет через settings owner из app, сохраняя дополнительную PublishRatios после Persist.
Pricing/catalog composition принадлежит leaf app; технические records/cache/publication state находятся
в adapters. Одноразовая request-specific SQL mutation capability передаётся shared mutation usecase
при Execute, без отдельного postcommit вызова и без общего изменяемого request state.

## Кэш проекций

Проекция всего каталога (цены провайдеров upstream, минимумы, дедупликация) — самая дорогая часть
чтения цен. Страницы `get_group_pricing`, `get_public_models` и `get_personal_pricing` строятся из
готового списка тарифа: `domain.EffectivePricingList` / `domain.PublicPricingModelsList` содержат
спроецированные модели в порядке имён, а страница только фильтрует, сортирует и режет их. JSON
страницы совпадает с прежним.

- Ключ — пара (группа пользователя, using group); на ключ хранится только последний список.
  Публичный каталог — один ключ `default`/`default`.
- Персональные списки — отдельный кэш: в них все модели тарифа, без фильтра подтверждённых цен,
  и каждая спроецирована (`EffectivePricingList.Projected`). Пользователь входит в проекцию только
  через условия `user_id` в param override каналов (`CatalogProviderAllowed`); группа пользователя
  уже в ключе. Есть ли такие условия, `Projection.CatalogOverridesReadUserID` проверяет один раз на
  отпечаток тарифа (`ProjectionCache.LoadUserDependence`). Без них пользователи тарифа делят один
  список, с ними у каждого пользователя свой. Личных списков не больше 8 на процесс
  (`UserListLimit`), лишний вытесняет давнее всего читавшийся.
- Персональная страница с сортировкой по имени без вкладки единиц берёт готовый список, а если его
  ещё нет, не ждёт: проецирует только свои модели, как раньше. Вкладка или сортировка по цене
  ждёт первого построения списка.
- Отпечаток входов `domain.PricingProjectionInputs`: ревизия потребительского каталога
  (`ConsumerPricingRevision`: снимок, группы, auto/usable groups, коэффициенты групп, FX) и
  набор billable-моделей (читается отдельно, кэш 1 минута, ревизию не меняет; `nil` в self-use
  отличается от пустого набора). Персональные списки billable-модели не фильтруют, их отпечаток —
  только ревизия.
- Изменился отпечаток — отдаётся прежний список (с его ревизией: `expected_revision` сверяется с
  отданным списком), а один фоновый пересчёт на ключ строит новый. Ждёт только запрос к ключу без
  списка; одновременные такие запросы делят одно построение (singleflight).
- Кэш — `adapter/pricing.ProjectionCache`; фоновые построения запускает `app/pricing.go`
  (`runPricingProjectionBuild`: recover и лог), прогрев тарифа `default` — `StartPricingProjectionWarmup`
  после первой загрузки FX (`pricingfx.StartModelCostFX`), не блокируя старт. Там же
  `get_personal_pricing.Usecase.WarmUp` строит общий персональный список группы `default` тем же
  путём, что и запрос (ключ `default`/пустой using group: персональные страницы using group не
  принимают). Если проекция зависит от `user_id`, общего списка нет и прогрев ничего не строит.
- Overview, карточка модели и полный каталог этим кэшем не пользуются.

## Курсы валют для стоимости

`refresh_cost_fx` загружает last-good baseline, получает provider facts, проверяет московскую
календарную дату и USD nominal, сохраняет новую публикацию через CAS либо возвращает прежнюю
версию при тех же дате/курсе. Version conflict не повторяется. Record `ModelCostFXRow` находится
в `adapter/gorm/pricing/record`, SQL и transaction — в `adapter/gorm/pricing/fx`, единственный RAM
cache и monotonic publication — в `adapter/pricing/fx`. Normalize/ошибки/публикация — pricing/domain.
`model.ModelCostFXRow` остаётся только table alias для bootstrap/migrations.

`app/pricingfx` собирает refresh один раз и запускает replica reload once на каждом узле:
немедленное чтение DB, затем minute ticker; scheduled refresh остаётся master-gated system task.
HTTP adapter `adapter/http/pricing/fx` сохраняет 10s timeout, запрет redirects, 1MiB limit и прежний
JSON wire type namespace `service`, чтобы диагностические error bytes не менялись. Package path
принадлежит adapter; прежних service FX bodies/facades нет. Billing читает только опубликованную RAM;
экономика, frozen basis, source/version и quota conversion остаются существующему billing owner.
